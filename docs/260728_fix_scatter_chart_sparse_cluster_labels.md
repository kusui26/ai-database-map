## 0. エグゼクティブサマリ（結論先出し）

- **事象**：`kmeans` が返すクラスタ番号に**欠番**（例 `{0, 2, 3}`）が生じると、`ScatterChart` は `clusterCount`（＝**種類数**）ぶんの dataset しか作らないため、**最大番号の点が一切描画されない**。エラーも警告も出ない **silent data loss**。
- **再現済み（実測）**：1 次元 7 点 `x=[2,2,8,7,1,0,12]` で `labels=[0,0,2,2,0,3,2]` → `clusterCount=3` → dataset の点数 `[3, 0, 3]` → **描画 6 点 / 全 7 点**（`x=0` の駅が消える）。`buildGrowth` → `scatterPanel` の**domain 実経路でも同一**（§3.1）。
- **発生条件と頻度**：**小標本かつ離散値**のときに限り、ランダム探索で **0.005–0.01%**（n=7–15）。n≥20 は 20,000 試行中 **0 件**（§3.2）。
- **実データの現況**：`/api/growth` を **576 組合せ**（6 指標ペア × 48 エリア × 除外 2）走査して **0 件**。ただし **n=5–11 の小標本ケースが実在 8 件**（地価増減率 × 人口増減率＋低分母除外の地方県）＝**リスク域は現実に存在**し、データ更新・指標追加・複数県選択で踏みうる（§3.3）。
- **副次の不整合**：件数キャプション「N駅・Mクラスタ」と AI 応答の要約は `points.length` 由来で**正しい数**を出すため、**表示件数と実描画点数が食い違う**。さらに空 dataset が 1 つできる分、**クラスタと配色の対応が 1 つずれる**。
- **修正方針（推奨）**：**`kmeans` が返すラベルを昇順で連番に詰める**（欠番を作らない）。JSDoc が既に謳う「0..k-1 を返す」の**実質的な契約を成立させる**修正で、`presenter` / Protocol / API / UI / AI は**無改変のまま正常化**する。連番が保たれている通常ケースでは**恒等変換＝現行描画と完全に同一**（回帰なし）。
- **再発防止**：「`cluster` は必ず `0..clusterCount-1` の連番」という**不変条件テスト**を domain テストに追加する。

## 1. 事象の定義

`ScatterChart` は「クラスタ番号 = `0 … clusterCount-1`」を前提に dataset を作る：

```ts
// src/components/panels/ScatterChart.tsx:39-42
const count = Math.max(1, panel.clusterCount)
return Array.from({ length: count }, (_, c) => panel.points.filter((p) => p.cluster === c))
```

一方 `clusterCount` は**種類数**として作られている：

```ts
// src/domain/growth/presenter.ts:63-70
const clusters = kmeans(kept.map((p) => ({ x: p.x, y: p.y })))
const points = kept.map((p, i) => ({ ...p, cluster: clusters[i] ?? 0 }))
…
clusterCount: new Set(clusters).size,   // ← 種類数（max+1 ではない）
```

**ラベルが連番なら両者は一致**する（`{0,1,2,3}` → 4）。しかし**欠番**があると一致しない（`{0,2,3}` → 種類数 3・最大値 3）。このとき UI は `c = 0,1,2` の dataset しか作らず、`cluster === 3` の点は**どの dataset にも入らない＝描画されない**。

## 2. 根本原因

### 2.1 生産側と消費側の前提のズレ

| 層 | 前提 | 実際 |
|---|---|---|
| 生産（`presenter`） | `clusterCount` ＝ **クラスタの種類数** | 正しい |
| 契約（`protocol` / `api`） | `cluster: number` ／ `clusterCount: number` — **両者の関係を規定していない** | 不変条件が**未定義** |
| 消費（`ScatterChart`） | `0..clusterCount-1` が**すべての**ラベル | **欠番があると破綻** |

型（`z.number()`）でも JSDoc でも「連番であること」が保証されておらず、**UI 側の暗黙の仮定**として残っていた。

### 2.2 なぜ欠番が生じるか（k-means の空クラスタ）

`kmeans`（`src/domain/growth/kmeans.ts`）は Lloyd 反復で、**点を 1 つも持たない重心**が生じても重心をそのまま残す：

```ts
// :121-125  count > 0 のときだけ重心を更新＝空クラスタは前回位置で存続
if (count > 0 && s !== undefined) centroids[c] = [s[0] / count, s[1] / count]
```

空クラスタが**末尾の番号**なら、残るラベルは `{0,1,2}` のように連番のままで**無害**。**中間の番号**が空になったときだけ `{0,2,3}` のような欠番になり、**有害**（描画漏れ）になる。

### 2.3 なぜ「稀」なのか（観測と整合する機構）

大規模探索（20 万試行）では **空クラスタ 14,851 件に対し、欠番はわずか 15 件**だった。この強い偏りは k-means++ 初期化の性質で説明できる：

- 初期重心は**距離に比例した確率**で選ぶため、既存重心と同一座標の点（距離 0）は通常選ばれない → 重心は相異なるデータ点になる。この場合、**初回割当では各クラスタが自分のシード点を必ず持つ**（タイブレークは `d < bestDist` で低 index 優先）。
- 相異なる座標が k 個未満しかない入力では、候補が尽きた時点で `total = 0` → `threshold = 0` → **先頭の点が重複重心として選ばれ、配列の末尾に追加**される。重複重心は同点のタイブレークで必ず負けるため、**空になるのは末尾の番号**＝ラベルは連番のまま。
- したがって欠番は「**2 回目以降の反復で中間クラスタが空になる**」場合に限られる（＝稀）。

> ⚠ 稀ではあるが**構造的に排除されていない**。現状は「たまたま踏んでいない」だけで、データ更新（年次差し替え・指標追加）や利用パターン（複数県選択・低分母除外・小標本エリア）で踏みうる。

## 5. 修正方針（案の比較）

| 案 | 内容 | 評価 |
|---|---|---|
| **A（推奨）** | **`kmeans` が返すラベルを昇順で連番に詰める**（欠番を除去）。JSDoc の契約を「0..m-1（m ≤ k・欠番なし）」に明確化 | 単一の原因を発生源で断つ。`presenter`・Protocol・API・UI・AI は**無改変で正常化**。**通常ケースは恒等変換＝現行描画と完全一致**。純関数・テスト容易（CLAUDE.md §3） |
| B | `presenter`（`buildGrowth`）で詰める | 効果は A と同等だが、`kmeans` の戻り値は欠番のまま＝**将来の別の消費者が同じ罠を踏む**。契約は発生源に置くのが筋 |
| C（任意・併用可） | `ScatterChart` の dataset 構築を「**実在ラベルでグルーピング**」に変更（1 パスの Map）。`clusterCount` は表示キャプションのみに使う | 描画側が上流の不変条件に依存しなくなる。O(clusterCount × n) → **O(n)** で単純化にもなる。ただし A があれば必須ではない |
| D | Zod に `refine` を足して実行時に不変条件を検証 | 違反時に**応答全体が 500 になる**（点が 1 つ落ちるより悪い UX）。不変条件は**単体テストで担保**するのが適切 → **却下** |
| E | 空クラスタが出たら重心を再シードして必ず k 個にする | クラスタリング結果自体が変わり、決定性・既存の見え方に影響。事象の解決に不要 → **却下** |

### 5.1 案 A の骨子（実装イメージ）

```ts
/** ラベルを昇順で 0..m-1 に詰める（欠番を除去・連番なら恒等）。 */
function compactLabels(labels: readonly number[]): number[] {
  const order = [...new Set(labels)].sort((a, b) => a - b)
  const rank = new Map(order.map((label, index) => [label, index]))
  return labels.map((label) => rank.get(label) ?? 0)
}
```

- **昇順で詰める**理由：ラベルが既に連番の通常ケースで**恒等変換**になり、**現行の色割当・見た目が 1 ピクセルも変わらない**（回帰ゼロ）。
  - 代替（不採用）：**出現順**＝先頭点のラベルが 0 になる。連番ケースでも並びが変わりうるため既存の見え方が変化する。**クラスタサイズ降順**＝「色 1 = 最大クラスタ」と意味づけできるが、同じく既存の見え方が変わる（クラスタ番号に意味を持たせない現行方針とも不整合）。
- `kmeans` の戻り値のみを変更し、**引数・決定性・クラスタリング結果（どの点が同じ集団か）は不変**。
- 20 行未満・純関数・`as` 不使用・`let` 不使用（CLAUDE.md §3）。

### 5.2 案 C の骨子（併用する場合）

```ts
const clusters = useMemo(() => {
  const byCluster = new Map<number, ScatterPoint[]>()
  for (const point of panel.points) {
    const bucket = byCluster.get(point.cluster) ?? []
    bucket.push(point)
    byCluster.set(point.cluster, bucket)
  }
  return [...byCluster.entries()].sort((a, b) => a[0] - b[0]).map(([, points]) => points)
}, [panel.points])
```

配色は現行どおり `clusterColor(index)` を dataset の並び順に適用する（欠番があっても色は循環内に収まる）。
