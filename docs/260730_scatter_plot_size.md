# 散布図モーダルの拡大（幅 896px ＋ 高さ可変）

作成日: 2026-07-30 ／ 対象: `src/components/scatter/ScatterDialog.tsx`・`src/components/panels/ScatterChart.tsx` ／ 依頼: 「散布図とランキングの画面を横に大きくしたい。画面端までの余白の 1/3 か 1/2 か」

> §1–§2 が選択肢と**事前比較の実測**、**§3 が確定した決定事項、§4–§5 が実装と検証結果**（2026-07-30 実装・検証済み）。

---

## 0. エグゼクティブサマリ（結論先出し）

- **当初の想定は実測で外れた**：幅 672px でも**駅名の省略は 0 / 51 件**、ピッカ段の高さも 672 / 896 / 1024px で**すべて同じ 95px**。「広げれば省略が消える・折返しが減る」は起きない。
- **ランキングは広げても得るものがない**：増えるのは行中央の余白だけで、駅名（左端）と値（右端）の視線移動が伸びる。1024px では選択メニューも不自然に間延びする。
- **散布図は幅だけ広げると逆効果**：チャート高さが 340px 固定のため、縦横比が **1.88:1 → 2.54:1（896px）→ 2.92:1（1024px）** と横長化し、密集クラスタが帯状に潰れる。
- → **非対称案を採用**：**散布図のみ 896px に拡大し、チャート高さを画面追従（最大 440px）に**。**ランキングは 672px のまま据え置き**。
- **結果（1440×900 実測）**：canvas **640×340（1.88:1）→ 864×432（2.00:1）**。**描画面積は約 1.7 倍**で、縦横比は理想の 2:1 に収まった。モーダルは `max-h-[88vh]` の内側（686 / 792px）で、本文スクロールも発生しない。

## 1. 選択肢（画面端までの余白をどれだけ使うか）

追加幅 =（画面幅 − 672）× 1/3 または 1/2。

| 画面幅 | 現状 | 1/3 案 | 1/2 案 |
|---|---|---|---|
| 1280 | 672 | 875 | 976 |
| 1440 | 672 | **928** | **1056** |
| 1920 | 672 | 1088 | 1296 |
| 2560 | 672 | 1301 | 1616 |

Tailwind の固定値では 1/3 ≒ `max-w-4xl`（896px）、1/2 ≒ `max-w-5xl`（1024px）が近い。**画面比のままだと大画面で 1300–1600px まで伸びる**ため、いずれにせよ上限は必要。

## 2. 事前比較の実測（672 / 896 / 1024px × 1440・1920）

リポジトリを変更せず、Playwright から `max-width` を上書きして 12 枚を撮影し、客観指標も測定した。

| 幅 | ランキング：駅名の省略 | ランキング：ピッカ高 | 散布：canvas | 散布：縦横比 |
|---|---|---|---|---|
| **672**（現状） | **0 / 51 件** | 95px | 640×340 | **1.88:1** |
| **896** | 0 / 51 件 | 95px（不変） | 864×340 | **2.54:1** |
| **1024** | 0 / 51 件 | 95px（不変） | 992×340 | **2.92:1** |

- 1440・1920 のどちらでも同じ傾向（ランキングの高さは `h-[86vh]` のため画面高だけで決まる）。
- 散布のタイトルは 672px では 2 行に折り返すが、**896px 以上で 1 行**に収まる（数少ない実利）。
- ランキングは幅を足しても**表示できる情報が増えない**（列は 4 つで飽和）。

## 3. 決定事項（2026-07-30 ユーザー承認）

| # | 決定 |
|---|---|
| 1 | **散布モーダルのみ拡大**：幅 `max-w-2xl`(672) → **`max-w-4xl`(896)** |
| 2 | **チャート高さを引き上げ**：固定 340px → **`clamp(300px, 48vh, 440px)`**（幅と合わせて縦横比 2:1 前後を保つ） |
| 3 | **ランキングは 672px のまま据え置き**（幅を広げる利得がないため） |

**理由**：①散布は「面積」が情報量に直結し、幅だけでなく高さを上げてこそ効く。②ランキングの制約は横ではなく**縦**（すでに `h-[86vh]`）。③大画面で無制限に伸びないよう上限（440px / 896px）を設ける。

## 6. 設計上の注記・将来の選択肢

- **なぜ固定 440px ではなく `clamp` か**：固定にすると 768px 級の画面でモーダルが `88vh` を超えて本文がスクロールし、「1 画面で散布を見る」体験が崩れる。`48vh` を挟むことで、画面が低いほど自動的に縮む。
- **ランキングを広げたくなった場合**：幅の拡大だけでは余白が増えるだけなので、**行レイアウトの変更**（値を駅名の近くに寄せる／行の内容幅に上限を設ける）とセットで検討する。
- **1/2 案（1024px）を採らなかった理由**：縦横比 2.92:1（高さ据え置き時）と、大画面での間延び。高さも上げれば成立しうるが、`88vh` 内に収める余裕が小さくなる。
