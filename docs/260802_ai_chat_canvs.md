# AI チャットの回答を「キャンバス」に分離する（実装プラン）

作成日: 2026-08-02 ／ 対象: チャット UI・散布/ランキングのダイアログ・アプリシェル
／ 依頼: 「回答で散布図やランキング、グラフを表示する場合は**右横にキャンバス**として出す。
テキストの回答は従来どおりチャット内。キャンバスの散布図・ランキングは**手動でも操作できる**ように。
初期表示はチャットのみ（**地図を既定で隠さない**）」

> §1–§8 が調査と設計、**§9 が確定した決定事項**（2026-08-02 ユーザー承認）、§10 以降が実装結果。
> 数値はすべて 2026-08-02 の実測。

---

## 0. エグゼクティブサマリ（結論先出し）

- **キャンバスは「⤢ 昇格先をモーダルからインラインに変える」だけで実現できる。** 既に
  `chatStore.promotion`（散布/ランキングの**全パラメータ**）と `PromotionHost`（それをダイアログで開く）が
  あり、AI の条件を復元する仕組みは**完成している**。出し先を差し替えるのが設計の中心。
- **「手動でも操作できる」は、ダイアログの中身をそのまま置くことで満たす。** `StationDetailPanel` が
  既に `DetailBody` を切り出してデスクトップ aside とモバイル Drawer で共用している——**同じ前例に倣い**
  `ScatterBody` / `RankingBody` を切り出す。フィルタ・指標ピッカ・ページングがそのまま動く。
- **サイズは 896 × 808px が最適**（実測）。幅 896px は散布ダイアログと同一で、**チャートの実寸と縦横比
  （864×432px＝2.00:1）が PR #37 で調整した値と 1px も変わらない**。高さはパネル枠（`top-20 bottom-3`）で
  808px となり、ランキングダイアログ（774px）より 34px 広い。
- **駅詳細は既にキャンバス相当がある。** 詳細の回答は `selectStation` を出すので**右ドロワーが自動で開く**
  （実測）。一方で散布・ランキングは地図操作を出さない（`growth` は無操作、`ranking` はハイライトのみ）
  ため、**キャンバスと詳細ドロワーは通常ぶつからない**。
- **既定で地図を隠さない**要件は自然に満たせる：キャンバスは `promotion === null` の間は**マウントしない**
  （初期状態は必ず null）。チャンクも遅延ロードで初期バンドルに載せない。
- チャット内のパネルは**参照チップ**（例「散布図：人口増減率 × 乗降回復率（全国・東海旅客鉄道・新幹線）」）に
  置き換える。テキストとグラフが分離され、履歴からの開き直しもできる。

### 1.2 回答の描画経路

```
/api/chat（SSE）
  ├ text パート ────────────────→ ChatMessage の吹き出し（RichText）
  ├ data-map.mapActions ───────→ useApplyMapActions → 地図・?grp（＝詳細ドロワー）
  └ data-map.panels ───────────→ buildPanelGroups → InlineCard（compact 描画）
                                      └ ⤢ → usePromote → chatStore.promotion
                                                            └ PromotionHost → モーダル
```

- `buildPanelGroups` は**ツール呼び出しの入力**から昇格パラメータを復元する。散布なら x/y キー・都道府県・
  運営会社・路線・種別・⚠除外まで**すべて**揃っている（PR #38〜#44 で拡張済み）。
- つまり「AI が出した図を、手動操作できる形で再現する」ための情報は**すでに揃っている**。

### 1.3 効果ごとの地図操作（`assemble.ts` 実測）

| 効果 | mapActions | 詳細ドロワー |
|---|---|---|
| 駅詳細 | `flyTo` ＋ **`selectStation`** | **自動で開く** |
| ランキング | `highlightStations` のみ | 開かない |
| 散布 | **なし** | 開かない |

→ **散布・ランキングのキャンバスは、詳細ドロワーと同時に出ることが通常ない**。
同時に出るのは「キャンバスの点/行をクリックして駅を選んだとき」だけで、これはユーザーの明示操作。

## 2. 設計の核心：昇格先を差し替える

`promotion` は既に「何をどの条件で描くか」の完全な記述になっている。**出し先だけを画面幅で切り替える。**

```
chatStore.promotion（ranking | scatter）
   ├─ 画面が広い（キャンバス可）  → ChatCanvas（インライン・地図の上に併設）   ← 新設
   └─ narrow / モバイル          → PromotionHost（従来どおりモーダル）        ← 既存のまま
```

- **新しい状態を増やさない**（`promotion` を再利用）。増やすのは「一度キャンバスに出した回答を覚える鍵」だけ（§5）。
- **`usePromote` は無改変**。チップの ⤢ も、キャンバス／モーダルのどちらへも同じ呼び出しで届く。
- FAB からの散布・ランキングは**モーダルのまま据え置く**（§9-5）。

### 2.1 ダイアログから中身を切り出す（前例あり）

`StationDetailPanel` は既にこの形になっている：

```
StationDetailPanel
  ├ isDesktop → <aside …>       <DetailBody … />
  └ mobile    → <Drawer.Content> <DetailBody … />
```

同じ形に揃える：

```
ScatterDialog  = <Dialog.Content>  <ScatterBody />     ← 中身は現状のまま移すだけ
RankingDialog  = <Dialog.Content>  <RankingBody />
ChatCanvas     = <aside …>         <ScatterBody | RankingBody />
```

`ScatterBody` / `RankingBody` は **`initial`（＝promotion）と `onSelect` を受け取り、フィルタ・指標ピッカ・
ページングを自前で持つ**（現状のダイアログとまったく同じ）。これで「手動でも操作できる」が満たされる。

## 3. キャンバスのサイズ（実測に基づく決定）

### 3.1 使える空間（チャット幅 400px・`left-3` は実測 12px）

キャンバスの左端＝ `12 + 400 + 12（余白）` ＝ **424px** 固定。

| 画面幅 | 空き（右余白 12 を除く）| 上限 896 を適用 | 地図の残り | 詳細ドロワー併用時の空き |
|---:|---:|---:|---:|---:|
| 1280 | 844 | 844 | **0** | 452 |
| **1440** | 1004 | **896** | **108** | 612 |
| 1536 | 1100 | **896** | 204 | 708 |
| 1728 | 1292 | **896** | 396 | 900 |
| 1920 | 1484 | **896** | 588 | 1092 |

高さは `top-20 bottom-3` ＝ **`100vh − 92px`**（900px 画面で **808px**）。

### 3.2 なぜ幅 896px か

- **散布ダイアログと同一**（`max-w-4xl`）。パディング 16×2 を引いた**チャート実寸 864×432px＝2.00:1** は、
  PR #37 で「幅と高さを対で調整して 2.00:1・面積 ×1.7」と決めた値そのもの。**キャンバスでも同じ見え方になる。**
- ランキング（ダイアログは 672px）も 896px で問題ない。PR #44 の実測どおり、絞り込み段は 3 コントロールで
  余裕があり、**表は駅名の省略が減って読みやすくなる**方向にしか働かない。
- **1 種類の幅に統一する**：散布 896／ランキング 672 と出し分けると、回答のたびに枠が伸縮して目が疲れる。

### 3.3 高さの使い方

| | ランキング | 散布 |
|---|---|---|
| ダイアログ（実測）| 774px（86vh）／表の可視 569px・行高 37px | 最大 792px（88vh）／チャート 432px |
| **キャンバス（808px）** | 表の可視が **+34px ≒ 1 行増** | チャートは **432px のまま**・余白が下に残る |

散布はチャート高を `clamp(300px, 48vh, 440px)` で固定しているため、キャンバスでは **170px ほど余る**。
**この余白は埋めない**（伸ばすと 2.00:1 の調整が崩れる）。将来「クラスタ凡例」等を置く余地として残す。

### 3.4 narrow のときの扱い

キャンバスに必要な最低幅を **672px（ランキングダイアログと同じ）** とすると、
必要な画面幅は `424 + 672 + 12` ＝ **1108px**。これ未満は**従来どおりモーダル**にフォールバックする。

- 1280px では地図が 0px になるが、キャンバスは**閉じられる**うえ、既定では出ないため要件に反しない。
- モバイル（`useIsDesktop` の 640px 未満）はボトムシート構成のため当然モーダル。

### 3.5 詳細ドロワーと重なるとき

キャンバスの点/行をクリックすると `?grp` が入り右ドロワー（幅 380）が開く。重なりを避けるため
**キャンバスの右端を `right: 12px` ⇄ `right: 404px` で切り替える**（`transition` 付き）。
1440px では 896 → **612px** に縮む。散布のチャートも追随して縮むだけで、破綻しない。

## 4. 何をキャンバスに出すか

| 回答の種類 | 現状 | 変更後 |
|---|---|---|
| **散布** | インラインカード（compact）＋⤢ でモーダル | **キャンバスに自動表示**（`ScatterBody`＝操作可）|
| **ランキング** | 同上 | **キャンバスに自動表示**（`RankingBody`＝操作可）|
| **駅詳細**（stationCard＋trendChart/statTable/barChart）| インラインカード＋⤢ でドロワー | **右ドロワーが従来どおり自動で開く**（＝既にキャンバス相当・操作可）|
| **markdown / テキスト** | 吹き出し | **変更なし**（チャット内） |

- 駅詳細をキャンバスに移さないのは、**すでに専用の操作可能パネル（タブ・半径）が右にある**ため。
  同じものを 2 か所に作ると状態が二重になる（CLAUDE.md §2 のアンチパターン）。
- チャット内には**参照チップ**だけを残す（§6）。

## 5. 自動表示のルール

```
「直近のアシスタント応答に散布 or ランキングがあれば、その promotion をキャンバスに出す」
```

- **純関数に切り出してテストする**：`canvasTargetOf(messages) → { key, promotion } | null`
  （`buildPanelGroups` を再利用。複数あるときは最後のものを採る）。
- **`key = messageId + 条件のハッシュ`** を覚え、**key が変わったときだけ**適用する。これで
  - 初期表示（メッセージ 0 件）では **null → キャンバスは出ない**（＝地図が隠れない）
  - ストリーミング中に data-map が段階的に届いても、**同じ図で開き直さない**（再フェッチが起きない）
  - ユーザーが閉じた後、同じ回答で**勝手に開き直さない**（key が変わらないため）
- **チャンクの遅延ロード**：`ChatCanvas` は `PromotionHost` と同じく `dynamic(..., { ssr:false })` で、
  初回に必要になるまで読み込まない（初期バンドル・LCP に影響なし）。

### 5.1 データの再取得について

キャンバスは `ScatterBody` / `RankingBody` を新規マウントするため、**表示時に 1 回 API を叩く**
（AI はサーバ側で取得しているのでクライアントキャッシュには無い）。現状の ⤢ 昇格とまったく同じ挙動で、
既存の「集計中…」表示がそのまま使える。実測レイテンシは散布 300〜600ms・ランキング 200〜300ms。
（AI の応答をそのまま SWR キャッシュに流し込む最適化は**今回対象外**。パネルは点/行しか持たず、
`GrowthResponse` 全体を復元できないため。）

## 6. チャット側の見た目（インラインカード → 参照チップ）

```
現状：  [ 東京駅周辺の人口は… ]
        ┌─────────────────────┐
        │ 散布図（compact 描画）  │  ← スレッドの中に図が積まれる
        │                  [⤢]│
        └─────────────────────┘

変更後：[ 東京駅周辺の人口は… ]
        [ 📈 散布図：人口増減率 × 乗降客数 コロナ前後増減率（全国・東海旅客鉄道・新幹線） ⤢ ]
```

- チップの文言は**パネルのタイトルをそのまま使う**（`scopeLabel` により絞り込み条件が入っている）。
  新しい文言を作らない＝表記のズレが生まれない。
- クリックで**キャンバスに再表示**（narrow ならモーダル）。過去の回答にも戻れる。
- 駅詳細のチップは従来どおり**ドロワーを開く**（`usePromote` が既に振り分けている）。

## 10. 実装結果 — PR1：`ScatterBody` / `RankingBody` の切り出し（2026-08-02・ブランチ `refactor/dialog-bodies`）

キャンバスとモーダルで同じ中身を使えるようにするための**純粋なコード移動**。
`StationDetailPanel` が `DetailBody` を aside と Drawer で共用しているのと同じ形に揃えた。

### 10.1 変更内容

| ファイル | 変更 |
|---|---|
| `src/components/scatter/ScatterBody.tsx`（新規）| 指標ピッカ・絞り込み・チャートを移設。**フラグメントを返す**ので、枠側の `flex flex-col` の子要素構成が変わらない |
| `src/components/ranking/RankingBody.tsx`（新規）| 絞り込み・指標ピッカ・表・ページングを移設（同上）|
| `ScatterDialog.tsx` / `RankingDialog.tsx` | 枠（オーバーレイ・ヘッダ・閉じる）だけの薄い殻に。**232 行削除・14 行追加** |

- `open` は Body では **`active`** という名前で受ける（「表示中だけ取得する」の意味を、モーダル以外でも通るようにするため）。
- 点/行クリックの `onSelect` は **枠側が決める**（モーダルは選択して閉じる／キャンバスは開いたまま）。
- 型（`ScatterInitial` / `RankingInitial`）は Body 側に置き、**再エクスポートしない**（CLAUDE.md §3）。

### 10.2 「見た目が 1px も変わらない」の検証

本番ビルドで **リファクタ前後を同条件で撮影**し、画素差分と実寸を比較した（1440×900）。

| 画面 | before vs after | **after vs after2（同一コード＝対照）** | before vs after2 |
|---|---:|---:|---:|
| 散布：既定 | **0** | **0** | **0** |
| 散布：東海旅客鉄道×新幹線 | **0** | **0** | **0** |
| ランキング：既定 | **0** | **0** | **0** |
| ランキング：東海旅客鉄道×新幹線 | 57 | **72** | 15 |

- **実寸は 3 回の撮影すべてで完全一致**（散布 896×710・チャート **864×432px＝2.00:1**／ランキング 672×774・行高 37px・各節の高さ）。
- ランキング（絞り込み後）だけ数十画素の差が出るが、**同一コードどうしの比較（72 画素）のほうが before/after（57 画素）より大きい**ため、リファクタ起因ではない。
