## 2. データ（取得元と、実測で確かめた事実）

### 2.1 課税対象所得・納税義務者数

**出典**：総務省『市町村税課税状況等の調』第11表（市町村別内訳）。
取得は **e-Stat API の社会・人口統計体系（SSDS）** 経由にする。

| 項目 | 内容 |
|---|---|
| 統計表 | `0000020103`（社会・人口統計体系 市区町村データ Ｃ経済基盤）|
| 指標 | `C120110` 課税対象所得（**千円**）／ `C120120` 納税義務者数（所得割）（**人**）|
| 年次 | 1985–**2024 年度**（更新 2026-06-19）。**2025 年度は未収録** |
| 地域 | 5 桁コード。**1,742 件に値**（どの年度も同数。うち 1 件が下記の集計行）|

**⚠ 実測で見つけた罠 ―「東京都 特別区部」が二重計上になる**

| | 課税対象所得（2024 年度・照合用）|
|---|---:|
| SSDS の 5 桁コード（末尾 000 を除く）を単純合計 | 255.3 兆円 |
| うち `13100 東京都 特別区部`（23 区の集計行）| **30.5 兆円** |
| **差し引き** | **224.8 兆円** |
| 総務省の原表（`J51-24-b.xlsx`・令和6年度）を全数集計 | **224.8 兆円** ✅ **完全一致** |

- **除外するのは `13100` の 1 件だけ。** 名称に「計／区部／市部／郡部」を含む 5 桁コードは
  これ 1 件しか存在しないことを全数確認した。
- **政令指定都市は「市計」（例 `01100 札幌市`）に値があり、行政区（`01101` 等）は `-`。**
  課税主体が市だからで、これは二重計上ではない（区に値が無いので足しても増えない）。
- 個別自治体でも一致を確認：千代田区・令和6年度 = 納税義務者 40,909 人／課税対象所得 480,902,182 千円
  （SSDS 2024 年度と原表 `J51-24-b.xlsx` が完全一致）。

**⚠ 年度の意味**：`N 年度` の課税は **N−1 年の所得**（住民税は前年所得に課税）。
実測でも 令和6年度（年度列 2024）= SSDS 2024 年度、令和7年度（年度列 2025）は SSDS 未収録だった。

**採用する 3 年度**（いずれも `13100` 除外後の実測値）

| 年度 | 所得の年 | 取得元 | 全国 課税対象所得 | 納税義務者 | 1 人当たり |
|---|---|---|---:|---:|---:|
| **2015 年度** | 2014 年 | SSDS API | 183.7 兆円 | 5,588 万人 | 329 万円 |
| **2020 年度** | 2019 年 | SSDS API | 204.2 兆円 | 5,940 万人 | 344 万円 |
| **2025 年度** | 2024 年 | **総務省 xlsx** | 241.0 兆円 | 6,221 万人 | 387 万円 |

**2025 年度だけ取得元が違う。** SSDS は 2024 年度までで、令和7年度（2025 年度）は
総務省サイトにしか無い（2026-07-31 掲載）。SSDS への反映は毎年 6 月頃なので、
**API だけに寄せると常に 1 年遅れる**。

**xlsx の URL は年度の西暦下 2 桁で決まる**ので、読み取りコードは 1 本で済む
（令和6年度と令和7年度でレイアウトが同一であることを実ファイルで確認済み）。

```

列      : 年度／団体コード／都道府県名／団体名／表側／所得割の納税義務者数／…／課税対象所得／…
採用行  : 表側 == "市町村民税"（1,741 行。道府県民税の行は使わない）
```

### 2.3 ⚠ 年次を 3 点に絞る理由（実測）

**2010 年以前は、メッシュに年齢別が存在しない。**

| 年 | 500m メッシュの項目数 | 1km メッシュ | 15〜64 歳 |
|---|---:|---:|---|
| 2020 / 2015 | （250m を使用）| — | **○ `0100`** |
| 2010 | 4 項目（人口総数・男・女・世帯総数）| 4 項目 | **✗** |
| 2005 | 4 項目 | 4 項目 | **✗** |
| 2000 | 4 項目 | 4 項目 | **✗** |
| 1995 | 4 項目 | 4 項目 | **✗** |

→ **重みの定義を揃えるため、所得の年次は 3 点**にする
（事業所・従業者と同じ 3 点なので、UI 上も違和感がない）。

「年をまたいで古い分布を流用しない」という原則（リサーチ §11.3 の教訓）に照らすと
2025 年度の 4 年差は上限に近い。**カタログの説明文に明記**し、2025 年国勢調査のメッシュが
公表されたら差し替える。

### 2.4 ⚠ 2024 年度を使わない理由（定額減税による異常）

年度をまたいだ推移を実測したところ、**2024 年度だけ納税義務者数が急減**していた。

| 年度 | 課税対象所得 | 納税義務者 | 1 人当たり |
|---|---:|---:|---:|
| 2022 年度 | 216.0 兆円 | 5,979 万人 | 361 万円 |
| 2023 年度 | 220.4 兆円 | 6,018 万人 | 366 万円 |
| **2024 年度** | 224.8 兆円 | **5,715 万人（−303 万人・−5.0%）** | **393 万円（+7.4%）** |
| **2025 年度** | 241.0 兆円 | 6,221 万人 | 387 万円 |

- **2024 年度の 1 人当たりは、翌年度（2025 年度）より高い**という逆転が起きる。
- SSDS の不具合ではない。**総務省の原表 `J51-24-b.xlsx` でも 5,715 万人**で一致した。
- 令和6年度は**定額減税**（所得割から 1 万円）が実施された年度であり、
  所得割額が 0 になった者が「所得割の納税義務者数」から外れたためと考えられる（断定はしない）。

→ **2024 年度を分母に使うと `inc_pc` が 7% ほど過大に出る**ので採らない。
2025 年度は 366 → 387 万円と自然な伸びで、正常値と判断できる。

## 3. 算出ロジック（方式A）

```
比率_m(R)     = （半径 R 内にある市区町村 m の 15〜64 歳人口）÷（市区町村 m 全体の 15〜64 歳人口）

inc_total(R)  = Σ_m  比率_m(R) × 課税対象所得_m          … 購買力の規模（百万円）
納税者(R)      = Σ_m  比率_m(R) × 納税義務者数_m
inc_pc(R)     = inc_total(R) ÷ 納税者(R)                 … 1 人当たり課税対象所得（万円/人）
```

- **分子と分母に同じ重みを使う**ので、半径が 1 市区町村に収まる場合 `inc_pc` はその自治体の値そのものになる
  （＝世間の「市区町村別平均年収」と一致し、検証しやすい）。
- 実装は既存の `_build_geom` / `aggregate_radii_multi` をそのまま流用できる。
  **市区町村ごとにメッシュを分けて集計する**点だけが新しい（メッシュ → N03 の空間結合を 1 回行い、
  メッシュに市区町村コードを付ける）。

### 3.1 メッシュ → 市区町村の割り当て

メッシュ（250m）は市区町村境界をまたぐことがある。**メッシュ中心点が属する市区町村に全量を割り当てる**
（面積按分はしない）。理由：

- 250m メッシュは市区町村面積に対して十分小さく、境界にかかるメッシュの割合が小さい
- 分母（市区町村の 15〜64 歳人口）も同じ規則で作るので、**比率_m の分子・分母で誤差が相殺する**
- 全国計の一致（§7）で検証できる

## 5. ノートブックへの実装（§（14）所得）

セル（13）事業所・従業者の後、CSV 出力（セル 50）の前に**マークダウン 1 枚＋コード 2 枚**を挿入する。

### 5.1 セル A：市区町村の所得データを読む

```python
# （14）所得（市町村税課税状況等の調・SSDS）→ 市区町村の課税対象所得・納税義務者数
INCOME_YEARS = [2015, 2020, 2025]          # 課税年度（値は前年の所得）
EXCLUDE_AREAS = {"13100"}                  # 東京都 特別区部＝23区の集計行（二重計上になる）
# → income_muni: index=市区町村コード(5桁), columns=[(year,'inc'),(year,'tax')]
```

- 入力は `data/市町村税課税状況/income_{年度}.csv`（§6 の取得スクリプトが出力・取得元が違っても同じ形）
- **全国計を原表と照合**して `assert`（2025 年度 **241.0 兆円** / **6,221 万人**）

### 5.2 セル B：メッシュに市区町村を付け、駅×半径へ按分

```python
# 15〜64 歳人口メッシュ（250m・2015/2020）を読み、N03 で市区町村コードを付与
# → 半径内の (市区町村, 15〜64歳人口) を集計 → 比率 → 所得・納税者を按分
WEIGHT_YEARS = {2015: 2015, 2020: 2020, 2025: 2020}   # 所得年度 → 使う国勢調査年（2025年調査は未公表）
```

処理の流れ：

1. `load_mesh_pop(mesh_dir, pop_cat01=100)` で 15〜64 歳人口メッシュを読む（**既存関数に引数を渡すだけ**）
2. メッシュ中心点 × `N03-20260101.shp` を空間結合 → メッシュに 5 桁コードを付与（政令市の区は市計へ丸め）
3. 市区町村ごとの 15〜64 歳人口合計を求める（＝比率の分母）
4. 駅ごとに `aggregate_radii_multi` の要領で **市区町村別に**半径内人口を集計
5. 比率 × 所得 / 納税者 を合計 → `inc_total` / 納税者(R) → `inc_pc`
6. 半径単調化（`np.maximum.accumulate`）は `inc_total` にのみ適用（`inc_pc` は単調でなくてよい）

### 5.3 セル C：増減率・フラグ

```python
INCOME_PAIRS = [(2025, 2020), (2025, 2015)]   # 5年 / 10年
INC_LOWN_TAXPAYERS = 1000                      # 納税義務者がこれ未満なら 1 人当たりが不安定
SEIREI_CITY_CODES = {...}                      # 政令市 20 市の市計コード
```

- `inc_gr_{新}_{旧}_{R}` = `inc_pc` の増減率（%）。分母年が 0/欠損なら NaN
- `inc_lown_{年度}_{R}` = 半径内の**納税義務者数 < 1,000 人** で 1
  （猿払村 1,450 人で 752 万円という実例があり、小さい分母で 1 人当たりが暴れる・§3.1）
- `inc_city_only_{R}` = 半径内に按分された納税義務者のうち、**政令市（市単位でしか値が無い）由来が 50% 以上**で 1
