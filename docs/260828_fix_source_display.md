## 1. 現状（実測・2026-08-28・PR #107 後）

### 1.1 寸法

| 要素 | デスクトップ（≥640px） | モバイル |
|---|---|---|
| 出典バー | 高さ **20px**・下端 0・右端 0（`padding: 0 5px`・角丸なし・ⓘ なし） | 同じ。FAB の上（`margin-bottom: 3.5rem`）・最大幅 `100vw − 3.5rem` |
| チャット・駅詳細の下端 | **36px**（`bottom-9`） | ボトムシート（変更なし） |
| FAB の下端 | **36px**（`sm:bottom-9`。以前は 16px） | 16px（変更なし） |
| 拡大縮小 | 下端 88px（`5.5rem`） | 既定 |
| 出典の最長（災害レイヤ ON） | **698px・1 行**（1280px でも収まる） | 2 行（40px） |

### 1.2 以前の見え方は「ⓘ 付きのピル」で、**ドラッグすると畳まれていた**

MapLibre 5.24 の既定は `compact: true` で、幅に関係なく**畳める形**になる
（`attribution_control.ts` の `_updateCompact`：`this._compact` が真なら常に compact）。
初期表示は展開（`maplibregl-compact-show`・角丸 12px・余白 10px・右端に ⓘ）だが、
**地図を 1 回ドラッグすると `_updateCompactMinimize` が畳む**（同ファイル・`drag` イベント）。
つまり以前は「最初だけ読めて、触ったら ⓘ だけ」だった。事務局の指摘はこれとパネルの裏隠れの合算である。

利用者が「元々あった丸いマーク」と呼ぶのは、この展開時の右端の ⓘ（`summary.maplibregl-ctrl-attrib-button`・
`svg/maplibregl-ctrl-attrib.svg`）である。

### 1.3 MapLibre 表記が消えた理由

```ts
// maplibre-gl/src/ui/control/attribution_control.ts
export const defaultAttributionControlOptions = {
  compact: true,
  customAttribution: '<a href="https://maplibre.org/" target="_blank">MapLibre</a>',
}
constructor(options: AttributionControlOptions = defaultAttributionControlOptions)
```

既定の `customAttribution` が MapLibre のリンクで、`{ compact: false }` を渡すと
**引数の既定値が使われなくなる**（マージではなく置き換え）。`defaultAttributionControlOptions` は
パッケージの公開 API に無い（`index.ts` で export されていない）ので、文字列をこちらで持つ必要がある。

**法的には不要**：MapLibre GL JS は BSD-3-Clause で、画面上の表記は求められていない
（求められるのは配布物への著作権表示）。ただし、①元からあった、②「提供元」の一部（描画エンジン）、
③消す理由が無い——の 3 点で**戻す**。幅は「MapLibre | 」で約 70px 増える。

## 2. 問い 1：FAB の置き場所

### 2.1 候補

| | A. 画面上部へ | B. チャット＋FAB を元の下端へ戻す（駅詳細だけ帯の上） | **C. 一直線を維持し、帯を「フッター行」に仕立てる（採用）** |
|---|---|---|---|
| 浮遊感 | 消える | 消える | **残るが、帯に中身（出典ピル・スケール）が入ると「フッターの上」に見える** |
| 出典との衝突 | 無い | **ある**（§2.2。1440px でも起きる） | 無い |
| 他の UI との衝突 | **ヘッダが既に満杯**（ロゴ・検索・半径・災害・AI）。警戒バナーも上に出る | 無い | 無い |
| 下端の揃い | — | **揃わない**（チャット 12px・駅詳細 36px） | 揃う |
| モバイル | 親指が届かない位置になる | 変更なし | 変更なし |
| 工数 | 大（ヘッダの再配置） | 小 | 小 |

### 2.2 B を採らない理由——出典が長いとき、FAB と同じ高さで必ずぶつかる

出典は右寄せで、**長くなると左へ伸びる**。FAB は左（チャットを開くと右へ退避）にある。
同じ高さに置く限り、幅が足りない画面では重なる。

- 出典の最長 ≒ 698px（実測）＋「MapLibre | 」70px ＋ ピルの余白 36px ＋ 右余白 10px ≒ **816px**
  → 左端は `画面幅 − 816`
- FAB 行 ≒ 320px（実測で確定する）。チャット開＝`x 440〜760`、閉＝`x 16〜336`

| 状態 | 衝突する画面幅 | 該当する端末 |
|---|---|---|
| チャット開（デスクトップの既定） | **幅 < 約 1,580px** | **MacBook Air 1440・Windows 125% の 1536**——ほぼ全部 |
| チャット閉 | 幅 < 約 1,160px | iPad 横 1024〜1180 |

しかもこれが起きるのは**災害レイヤ ON＝警戒モードで自動的にそうなる状態**で、出典がいちばん要る場面である。
折り返して 2 行にすれば横は逃げられるが、ピルが 44px になり、**駅詳細の下端を 56px まで上げる**ことになる
（稀な状態のために常時 20px 失う）。よって B は採らない。

### 2.3 C で浮遊感をどう抑えるか

FAB は定義上「浮く」ものなので、目指すのは「浮いている理由が見える」ことである。

1. **出典をピルにして下に余白**（§3.1）——帯が「意図した 1 行」に見える
2. **帯の左にスケールバー**（任意・§3.4）——地図の下端は「左にスケール・右に出典」が定石
   （Google マップ／Apple マップも同じ構成）。左に中身が入ると、FAB は「フッターの上に浮く」
   ものとして自然に読める。当アプリは半径で集計するので、スケールは飾りではなく役に立つ
3. **帯は 36px のまま**。広げるほど FAB は浮くので、余白は帯の中で取る

> 数値の補足：帯 36px ＝ 余白 6 ＋ ピル 24（行 20 ＋ 上下 2）＋ 隙間 6。
> 余白を MapLibre 既定の 10px にすると隙間が 2px になり、パネルの角とピルが接して見える。

## 3. 問い 2〜4：出典の見た目

### 3.1 余白（問い 2）

`margin: 0 10px 6px 0`。ピル（角丸 12px・`padding 2px 28px 2px 8px`・半透明の白）にする。
モバイルは今の `margin-bottom: 3.5rem`（FAB の上）に、右余白と角丸だけ揃える。最大幅の制限は残す。

### 3.2 ⓘ マーク（問い 3）——3 案

| | 案 1：飾り（押せない） | **案 2：About を開く（推奨）** | 案 3：`compact: true` に戻して畳まれないようにする |
|---|---|---|---|
| 見た目 | 元と同じ | 元と同じ | 元と同じ |
| 押したら | 何も起きない（`aria-hidden`） | **About（出典・ライセンス・何に使っているか）が開く** | MapLibre の畳む／開く |
| 出典が隠れる恐れ | 無い | 無い | **ある**。畳む動作は `drag` イベントと `summary` の既定動作に結びついていて、CSS で潰しても `<details>` の `open` 属性が外れると中身は消える。**内部実装に依存**し、版が上がると壊れる |
| 手間 | 最小（CSS の `::after`） | 小（About の開閉を store に出す・ボタン 1 個を DOM に足す） | 中（内部の挙動を打ち消す） |

**案 2 を推す。** ⓘ は「情報」の記号なので、押したら**権利表記の全文**（`hazardDataSources`・ライセンス・用途）へ
行けるのが自然で、事務局の「権利表記が確認できる」にもいちばん正面から応える。
案 1 は「押せるように見えて何も起きない」ので、案 2 を見送るときの次善。案 3 は採らない
（畳まれるボタンを復活させるのは、指摘の原因を戻すことになる）。

**実装の勘所（案 2）**：MapLibre の `summary` ボタンは `compact: false` でも DOM にあるが**表示してはいけない**
（`<details>` の `summary` なので、押すと既定動作で中身が閉じる）。代わりに**自前の `<button>`** を
`.maplibregl-ctrl-attrib` に足し、`AppHeader` の `aboutOpen`（いまは `useState`）を **`uiStore` に出して**
両方から開けるようにする。アイコンは MapLibre 同梱の SVG（BSD-3・パスは 1 本）をそのまま使う。

### 3.3 MapLibre 表記（問い 4）

戻す。`attributionControl: { compact: false, customAttribution: MAPLIBRE_CREDIT_HTML }`。
文字列は `shared/constants` に置き、テストで「消えていないこと」を固定する。

### 3.4 スケールバー（任意・問い 1 の補助）

`ScaleControl`（MapLibre 同梱・`maxWidth 120`・metric）を**デスクトップだけ**左下の帯に出す。
モバイルは左下に拡大縮小があり、帯も無いので出さない（CSS で非表示）。

- 拡大縮小と同じ `bottom-left` の器に入るので、器の余白（いま `5.5rem`）を**拡大縮小のグループだけ**に付け替え、
  スケールは帯の中（余白 6px）に置く
- チャットを開いていても、チャットの下端は 36px なので帯の中のスケールは隠れない

入れなくても他の項目は成り立つ（**独立**）。浮遊感の判断は §8 のスクリーンショットで見て決めてよい。

### 3.5 並び順（2026-08-28 追記・決定 6）

実装後に「左から MapLibre・国土地理院・ⓘ の順が最適か」と問われた。**いまの順は設計ではなく
MapLibre の実装の副産物**である——`AttributionControl._updateAttributions` は重複除去のために
全項目を**文字列の長さで昇順ソートし、その順のまま表示**する。HTML 込みの長さなので
MapLibre のリンク（約 70 文字）＜ 国土地理院のリンク（約 90 文字）となり、災害レイヤの出典
（素のテキスト・16〜24 文字）は最短で先頭に来る。災害レイヤ ON では
「キキクル | ポータル | MapLibre | 国土地理院」と、エンジンが提供元の間に挟まっていた。

**採る並び：「[重ねたデータの出典（あれば）] | 国土地理院最適化ベクトルタイル | MapLibre ⓘ」**

1. **提供元（法的に要る側）を先に、エンジン（任意の謝辞）を最後に**——事務局の関心は提供元
2. **右寄せのピルでは右端だけが動かない**。常に出る「国土地理院 | MapLibre ⓘ」を右端の固定ブロックにし、
   ON/OFF で増減する災害レイヤの出典は左（伸びる側）へ
3. **ⓘ は末尾のまま**（「詳しくは」の記号は文末が自然で、元の見た目とも同じ）

**直し方**：ソートは止められないが、同じ処理の**「部分文字列は消す」**を使う。
「国土地理院のリンク HTML | MapLibre」を **1 本の `customAttribution`** として渡すと、スタイルの
ソースが持つ国土地理院の出典はその部分文字列なので除かれ、こちらの 1 本だけが残る。
災害レイヤの出典（短い）はソートで必ずその左に付く。ベース地図の出典はスタイル
（`gsi-pale-style.json`）から `load` 時に読むので、スタイルを差し替えてもずれない。
災害レイヤどうしの順（キキクル → ポータル）は長さ順のままで、これは許容する。

- **状態**：平時／駅選択（チャット＋駅詳細）／災害レイヤ ON（出典が最長）／**ドラッグ後**（畳まれないこと）
- **見るもの**：出典ピルの矩形が画面内で、チャット・駅詳細・FAB・拡大縮小・スケールと重ならない。
  「MapLibre」と ⓘ が出ている。ⓘ を押すと About が開き、ヘッダの ⓘ と同じ内容
- **モバイル**：FAB の上・拡大縮小の右で読める（2 行に折り返してよい）
- **スクリーンショット**：§6-1・§6-5 の判断材料として、スケールあり／なしを並べて出す

## 9. やらないこと

- **FAB を上部へ移す**（§2.1 A）。ヘッダと警戒バナーの領域で、モバイルの親指も届かない
- **帯を広げる**。FAB が浮く問題を悪化させる。余白は帯の中で取る
- **出典コントロールの自作**（IControl の再実装）。ソースの表示状態・重複畳みを MapLibre が持っており、作り直す価値が無い
- **`compact: true` に戻す**（§3.2 案 3）。畳む動作＝指摘の原因を戻すことになる
- **出典の文言・データの出典一覧（About）の変更**。今回は置き方と見た目だけ
