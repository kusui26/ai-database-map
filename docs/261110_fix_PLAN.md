### 0.2 根は 1 つ

**「注意・限界・出典は、どの画面でも、常に、全部出す」を機能ごとに足してきた結果、主役の値と結論が埋もれた。**

- 概要：本文の **45%**（639 / 1,424 字）が「見ていないこと・注記・出典」
- エリア：本文の **42%**（978 / 2,333 字）が「凡例の写し・見ていないこと・注記・出典」。グラフは 3 画面目まで出てこない

1 つ 1 つは正しい理由で足した（§1.5）。足し合わせたら読めなくなった。

### 0.3 方針は 3 つ

1. **共通 API は減らさない。** 見ていないこと・注記・出典は応答に残す。AI は今までどおり本文で言う。減らすのは**画面の描き方だけ**（災害だけ、応答に 3 項目を足す）。
2. **画面は 3 段に分ける。** 常に見せる（値・結論・**その場所に固有の注意**）／押すと開く（根拠・どこでも同じ一般的な注意・出典）／画面には出さない（見ていないこと・読み方の注記）。災害は「安全という意味ではありません」の 1 文と免責を**必ず見える所に残す**。
3. **過去の決定を先に書き換える。** 今回は合意済みの決定を 5 つ覆す（§2.4）。コードより先に、決めた文書を直す。

### 0.4 この計画で分かった、依頼の外の論点（3 つ）

- **おすすめを外すと、UX の計画（`261019` §6）の U3 が成り立たなくなる。** U3 は「聞き取り → おすすめへ条件ごと渡す」で、行き先が無くなる（§3.5・決めてほしいこと D-2）。
- **ヘッダのバッジを外すと、災害タブへの入口が無くなる。** 災害タブは帯の右端（568〜620px）にあり、420px のパネルでは既定で完全に隠れている。バッジはそのための入口だった（§5.3・D-3）。
- **エリアの値の出典は、About に載っていない**（8 種類。横浜市の要約では 9 件のうち 5 件）。画面から外す・畳むなら、About に足す必要がある（§2.3）。

## 2. 方針（6 点に共通）

### 2.1 共通 API は減らさない——AI への影響を構造で断つ

`.claude/CLAUDE.md` §2 のとおり、意味（注記・見ていないこと・出典）は共通 API が持つ。**今回、応答から消すものは無い**（おすすめの API を除く）。

| 口 | 見ていないこと・注記・出典 | 今回 |
|---|---|---|
| 共通 API の応答（`/api/stations/[grp]/profile`・`/api/areas/summary`・`/api/hazard/point`） | 持つ | **変えない**（災害だけ 3 項目を足す・§8.4） |
| AI に渡す要約（`stationProfileForLlm`・`areaSummaryForLlm`・`hazardSummaryForLlm`）と `answerGuide` | 持つ | **1 文字も変えない** |
| MCP のビューア（`src/shared/viewer/panels.ts`） | 出す | **変えない**（MCP のホストには About が無い） |
| Web の画面（`src/components/panels/*.tsx`） | 出す | **ここだけ変える** |

だから、項目 2〜6 では Gemini の答えは変わらない（プロンプトも、道具の返り値も同じ）。**プロンプトを触るのは項目 1（おすすめ）だけ**で、そこだけ評価を A/B で流す（§10.3）。

概要とエリアの回答は、AI が本文で「見ていないこと」に触れる（`PROFILE_ANSWER_GUIDE_JA`・`AREA_SUMMARY_ANSWER_GUIDE_JA`）。`261001` §9.2 の原則 5「道具は『見ていないこと』も返す。AI はそれを本文に書く」は、そのまま守られる。

### 2.2 画面の 3 段

| 段 | 入れるもの | 例 |
|---|---|---|
| **常に見せる** | 値・結論。**その駅・そのエリアに固有の注意** | 「政令市の所得は市全体の平均が主です」「出せない値：人口の 2025 年」「土砂災害：この地域には想定区域図がありません」「250m メッシュの範囲での判断です」 |
| **押すと開く** | 根拠の文、どこでも同じ一般的な注意、分布の細部、出典 | 「洪水：白い場所は…という意味ではありません」、駅の周りの上位と下位、出典 9 行 |
| **画面に出さない**（応答と AI には残る） | 見ていないこと、読み方の一般的な注記 | 「治安・学区・家賃…」「順位は値の大きい順です…」「区域の値は公表値…」 |

線の引き方は「**固有か、どこでも同じか**」。固有の注意はその値の読み方を変えるので見せる。どこでも同じ文は、何度も出るほど読まれなくなる。

**災害だけは、安全側に 2 つ残す。**

- 「『該当なし』『想定区域図なし』は、安全という意味ではありません」の 1 文（該当しなかった災害があるとき、必ず見える所に）
- 免責（「実際の避難は、市町村の避難情報に従ってください」）

### 2.3 出典（利用条件）の扱い

出典の表示は利用条件なので、**画面から辿れなくはしない。**

1. 概要・エリアのパネルの出典は、**1 行に畳む**（「出典（8）」を押すと今と同じ一覧が開く）
2. **About にすべて載せる。** いまの About は駅の指標（`dataSources()`）・災害・路線・地図を載せているが、**エリアの値の出典は載せていない**。区域の指標のカタログ（`src/shared/catalog/area-catalog.json`）の出典は 8 種類あり、どれも駅の指標のカタログ（9 種類）に無い。横浜市の要約では、9 件のうち次の 5 件が About に無い

   - 総務省 国勢調査（e-Stat 社会・人口統計体系 市区町村データ）
   - 総務省 令和7年国勢調査 人口等基本集計
   - 経済センサス‐活動調査（市区町村データ）
   - 国土数値情報 将来推計人口メッシュ（R6）を市区町村ごとに足したもの
   - 同（2070 年まで延長した分）

   沿線では、メッシュを面積で按分した 3 種類（国勢調査 250m・将来推計人口 250m・経済センサス 500m）が同じく無い。

   区域の指標のカタログ（`src/shared/area-catalog.ts`）から出典を束ねる純関数を足し、About に「エリア（市区町村・沿線）の値」の節を作る。手で書かない（災害の出典と同じ作法）。
3. 災害のパネルの出典は**今のまま見せる**（1〜2 行と短く、`260824` §7.5-3「年度と出典を常時表示」を守る）
4. 地図の出典の帯（`tests/map-attribution.test.ts`）は触らない
