# エリアの区域の値（行政区域の公表値・沿線のメッシュ按分）

作成日：2026-10-10 ／ B5a（`docs/261001_fix_user_feedback_ui.md` §6.12 の設計を実装したデータの説明）

「横浜市全体の人口は？」「東急東横線の沿線の人口は 2050 年までにどうなる？」に、**区域全体の値**で答えるためのデータ。
駅の半径の値（`station_values`）とは別に、エリア（行政区域と沿線）を単位とした人口（実績・推計）・事業所・従業者を持つ。

> ⚠ **駅の値を足して区域の値にしない。** 駅の円は重なっているので二重に数える。沿線 1km では、駅の値の和は区域の値より
> 中央値で 19%、最大で 6 倍多い（§6.12.2）。区域の値はこの表から読む。

|---|--:|---|---|---|

| `prefecture` 都道府県 | 47 | `pref:14` | — | `jp` |
| `city` 政令市（市全体） | 20 | `muni:14100` | 区を束ねる | 都道府県 |

| `municipality` 市区町村 | 1,721 | `muni:14341`（大磯町）・`muni:13101`（千代田区） | 行政区域（N03 2026） | 都道府県 |

| `line` 沿線 | 1,803 | `line:26001@1000` | 路線（運行系統・601 本）の駅から 500m・1km・2km の円を重ねた範囲 | — |

- 鍵は共通 API・URL・地図の操作で同じ形を使う（§6.12.3）。名前（`name_ja`）は駅の市区町村（`stations.municipality`）と同じ言い方
  （政令市の区は「横浜市港北区」）、題（`label_ja`）は都道府県を前に付ける（「神奈川県横浜市港北区」）

## 3. 行政区域の値（公表値）

**メッシュから作り直さない。** 全国の市区町村でメッシュを按分すると、公表値と人口で中央値 0.19%・最大 11.3%、従業者で
中央値 0.78%・最大 29.2% ずれた（§6.12.4 a。`validate_area_values.py --mesh` で再現できる）。

| 値 | 区・市区町村・政令市・東京 23 区 | 都道府県・全国 |
|---|---|---|
| 人口 1995〜2020 | 社会・人口統計体系 市区町村データ（**廃置分合処理済**）`0000020201`・A1101 | 同 都道府県データ `0000010101`・A1101 |
| 人口 2025 | 令和 7 年国勢調査 人口等基本集計 `0004065881`（総数） | 同じ表 |
| 将来推計人口 | 国土数値情報 将来推計人口メッシュ（R6）の `PTN_<年>` を `SHICODE` ごとに足す | R6 を都道府県・全国で足す |
| 事業所・従業者 | 社会・人口統計体系 市区町村データ（廃置分合処理済）`0000020203`・C2108／C2208 | 各年の経済センサスの公表値（2012 `0003085523`・2016 `0003218501`・2021 `0004005640`） |
| 面積 | 令和 7 年国勢調査（面積・参考）`0004065882` | 同じ表 |

- **今の境域**：社会・人口統計体系の「廃置分合処理済」は、過去の年の値も今の市区町村の境域に組み替えてある（例：栃木市の 2012 年は
  2014 年に合併した岩舟町を含む）。経済センサスの「年」は**年度**の表記で、2012 年 2 月の活動調査は「2011 年度」
- **都道府県・全国は公表の行を使う**（市区町村の和にしない）：都道府県の値には市区町村ではない区域も入る
  - 境界未定地域（`13199`・東京湾の埋立地）：経済センサスにだけあり、東京都と東京 23 区の値に入る（2021 年 458 事業所・12,625 人）
  - 境域の変わり方：長野県山口村（2005 年に岐阜県中津川市へ越県合併）と山梨県上九一色村（2006 年に分かれて編入）は、
    その年の県の値には入るが、今の境域に組み替えた市区町村の値とは合わない（差は旧村の人口と 1 人単位で一致・`area_rules.PREFECTURE_SUM_EXCEPTIONS`）
- **将来推計人口**：R6 の各セルには市区町村コード（`SHICODE`）が 1 つ付いている（県をまたぐ 865 セルだけ県ごとに 2 行）。`SHICODE` ごとに足すと、
  2020 年は国勢調査と全 1,876 市区町村で 1 人単位、2025〜2050 年は社人研の地域別推計（令和 5 年推計）と全市区町村・政令市・都道府県
  13,601 組で 1 人単位で一致する。2055〜2070 年は国交省の延長。推計は 2020 年が起点で、2025 年の実績とは市区町村の中央値で 1.29% 違う
  （64% で推計が多すぎた。横浜市は実績が推計より 0.9% 少ない）
- **浜松市**（2024-01 に 7 区 → 3 区）：中央区・浜名区の値は 2020・2025 年の人口だけ（2020 年は 2025 年の国勢調査の組替）。
  天竜区は範囲が変わらずコードだけ変わったので（22137 → 22140）、過去の値も推計もある。市全体の値はすべてある
- **福島県の浜通り 13 市町村**：社人研は個別の推計を出していない（R6 も `07999` にまとめている）。推計は福島県・全国の値には入る

## 4. 沿線の値（メッシュの面積按分）

- 範囲：路線（`data/derived/lines.csv`・駅データ.jp の運行系統 601 本）の駅から W の円を重ねた 1 つの面（W＝500m・1km・2km・既定 1km）。
  線路の形は持っていないので、沿線は駅勢圏（駅の円）で決める
- 方法：駅の半径の値と**同じ**（正積図法 Albers・円は 32 分割・セルと面の重なりの割合だけセルの値を数える＝セルの中は一様と置く）。
  円が重ならない沿線（6,042 組）では、沿線の値が駅の円の値の和と一致する（差は駅 1 つあたり最大 0.48＝駅の値の四捨五入の分）
- 年：人口 2015・2020 年（250m）、推計 2020〜2070 年（R6・250m）、事業所・従業者 2012・2016・2021 年（500m）。
  2010 年以前の人口は 500m で、250m の年と比べると段差が出るので作らない（`docs/population_mesh.md` §6.3）。**2025 年は無い**
  （2025 年の国勢調査のメッシュは未公表・2026-10-10）。幅 500m の沿線では、500m の経済センサスのセルは粗い
- 将来の増減は**推計の中で比べる**（`pop_pred_2024_2020` を起点に・§12-23）。沿線では推計の 2020 年と国勢調査の 2020 年が少し違う
  （1km で中央値 0.59%）。東急東横線 1km：国勢調査 2020 年 760,069 人、推計 2020 年 750,165 人 → 2050 年 787,122 人（+4.9%）

## 5. 無い値と理由（`areas.missing`）

無い値は必ず理由を持つ（理由の無い欠けは build が落とす）。規則は `area_rules.MISSING_RULES`。

| 区域 | 無い値 | 理由 |
|---|---|---|
| 政令市の区（42 区） | 区ができる前の年の人口・事業所・従業者 | その年はまだ区が無かった（市全体の値はある） |
| 浜松市中央区・浜名区 | 人口 1995〜2015・推計・事業所・従業者 | 2024 年の区の再編。推計と経済センサスは再編前の 7 区 |
| 浜通り 13 市町村 | 推計 | 社人研が個別の推計を出していない |
| 避難指示区域の 7 町村 | 事業所・従業者 2012 | 2012 年の経済センサスは調査されていない |

## 6. 置き場所と量

| 段 | ファイル | 中身 |
|---|---|---|
| 規則 | `pipeline/area_rules.py` | 年・幅・e-Stat の表・単位の特例・無い値の理由・県の和の例外・照合の固定値・指標の定義（**手で編集するのはここだけ**） |
| 取得 | `pipeline/fetch_area_stats.py` | e-Stat の 8 表と社人研の結果表（照合用）→ `data/area_raw/`（appId と URL は出さない） |
| 行政区域 | `pipeline/build_area_values.py` | → `data/derived/area_units.csv`・`area_values.csv`・`src/shared/catalog/area-catalog.json` |
| 沿線 | `pipeline/build_line_corridors.py` | → `data/derived/line_corridors.csv`・`line_corridor_values.csv`（601 × 3 幅・約 2 分） |
| 検証 | `pipeline/validate_area_values.py` | 独立の検証（推計＝社人研・固定値・沿線の不変条件・形・`--mesh`） |
| 投入 | `pipeline/load_area_values.py` | → DB の `area_metrics`・`areas`・`area_values`（単一トランザクション・投入後の確認が崩れたらロールバック） |
| DB の検証 | `pipeline/golden_area_values_test.py` | 本物の DB と PostgREST（anon）で 20 項目 |

- DB：区域 3,764・値 80,994・3 つの表で 6.3MB（DB 全体 432MB → 439MB・無料枠 500MB）。値は double precision
  （全国の人口 1.2 億人は real では 1 人単位で持てない）。RLS・anon は SELECT だけ
- 共通メッシュの読み方（`pipeline/area_mesh.py`）は、駅の値を作ったノートブックと同じ規約（デコーダ・正積図法・円の分割）

```bash
python3 pipeline/fetch_area_stats.py          # 公表値（取得済みなら skip・--force で取り直す）
python3 pipeline/build_area_values.py         # 行政区域（照合が崩れたら書かない）
python3 pipeline/build_line_corridors.py      # 沿線（路線・駅を作り直したら、ここから）
python3 pipeline/validate_area_values.py      # 独立の検証（--mesh でメッシュの按分と公表値のずれも）
python3 pipeline/load_area_values.py          # DB へ
python3 pipeline/golden_area_values_test.py   # DB の黄金テスト（当てる前は --trial）
python3 pipeline/build_area_values.py --check # カタログ JSON が規則と一致するか（CI ではなく手元）
```

## 7. 更新の手順

- **行政区域（N03）の年版**（合併・区の再編）：`fetch_admin_boundaries.py` の版を上げ、build → validate → load。
  名前・コードが国勢調査の表とずれたら build が落ちる。新しい再編は `area_rules.py` に理由を書く
- **2025 年の国勢調査のメッシュ**が出たら：沿線の人口に 2025 年を足し（`LINE_POP_YEARS`）、駅の値（別の作業）とあわせて作り直す。
  2020 年のメッシュは調査から約 2 年後（2022-08-30）に出た
- **社人研の次の推計**・**国土数値情報の将来推計人口メッシュの次の版**：`R6` の読み方（`area_mesh.py`）とカタログの vintage を替える
- **経済センサス‐活動調査（2026 年）**：`ECON_YEARS` と `ESTAT_TABLES` に足す（全国計を公表値と照合する）
