# データセット（AI Database Map）

Step1 の中核資産である駅×半径データセットの**全体像・全カラム一覧・拡張ワークフロー**をまとめる。開発指針の正は [`.claude/CLAUDE.md`](../.claude/CLAUDE.md)、各データの詳細設計・監査は `docs/` の個別ドキュメント（末尾§6）。

---

## 1. 概要

- **生成物**：`script/create_dataset_for_AI_Database_Map.ipynb` → **`data/derived/station_dataset.csv`（9,273 駅グループ × 595 列）**。あわせて監査明細 `station_operator_detail.csv`（1群×1社）、地価パネル `station_landprice_yearly.csv`（ロング形式）を出力。
  - **P5d（2026-07-09）**：`station_dataset.csv` を「すべてを含む単一ベース」に統一。地価中央値を**年次系列 `lp_med_{年}_{R}`（2007–2026・単年 `lp_med_{R}` を置換）**にし、運営会社名を `operators`（1群×1社を pax 規模降順で `・` 連結した単一文字列）として畳み込む。監査 CSV（yearly / operator_detail）は温存。UI/API/AI はカタログ再生成＋再ロードで自動追従。
- **単位＝駅グループ（`grp`）**：同名・近接駅を 1km クラスタで統合した駅単位（`docs/passenger_aggregation.md`）。1 行 1 駅グループ。
- **半径**：**500m / 1km / 2km / 5km / 10km / 20km**（過去プロジェクトの 1/2/5/10km を刷新・統一。※地価のみ後述の理由で 500m–10km）。
- **CRS**：基準 **EPSG:6668（JGD2011）**、距離・面積計算は **Albers 正積投影**（`docs/CRS.md`）、メッシュはコードから緯度経度を復元。
- **列命名規約**：接頭辞（`pop_` / `lp_` / `bus_` / `estab_` / `emp_`）＋ 年 ＋ 半径サフィックス。増減率は `*_gr_{新}_{旧}_{半径}`、**信頼性フラグ**は `*_lowbase` / `*_lown`（低分母で率・中央値が不安定な駅を 1 で識別）。列名はすべて ASCII snake_case（値は日本語可）。
- **DB 取込**：`lon`/`lat` を保持し、geometry は取込時に `ST_SetSRID(ST_MakePoint(lon,lat),4326)` で生成する前提（`.claude/CLAUDE.md` §3）。

### 収録データと集約パラダイム
| 種別 | 出典 | 集約パラダイム | 接頭辞 |
|---|---|---|---|
| 乗降客数 | 国土数値情報 **S12** | 駅グループ集約（空間クラスタ）| `pax_` / `rate_` |
| 人口（1995–2020）| 国勢調査メッシュ（250m/500m）| **面積按分** | `pop_` |
| 将来推計人口 | R6（250m）・H30（500m）| 面積按分 | `pop_pred_` |
| 地価 | 国土数値情報 **L01** 地価公示 | 点の**中央値** | `lp_` |
| バス停 | 国土数値情報 **P11＋P36** | 点**カウント＋≤25m重複排除** | `bus_` |
| 事業所数・従業者数 | 経済センサス活動調査（2012/16/21）| 面積按分 | `estab_` / `emp_` |

## 2. 全カラム一覧（595列）

半径サフィックス `{R}` ∈ `{500m, 1km, 2km, 5km, 10km, 20km}`。増減率（`*_gr_*`）は分母年の値が 0 の駅で NaN。カウント・水準は 0 を有意値として保持（NaN にしない）。

### 2.1 識別・駅属性（10列）
| 列 | 型 | 説明 |
|---|---|---|
| `grp` | str | **駅グループID**（同名近接駅を 1km クラスタで統合した単位・主キー）|
| `station_name` | str | 駅名 |
| `label` | str | 表示用ラベル（複数社・同名衝突を整形）|
| `search_label` | str | 検索用ラベル |
| `prefecture` | str | 都道府県（行政区域 N03 を代表点に空間結合）|
| `lon` / `lat` | float | 代表点の経度・緯度（EPSG:6668）|
| `n_op` | int | グループ内の延べ事業者数 |
| `operators` | str | 運営会社名（1群×1社を pax 規模降順で `・` 連結。例「東日本旅客鉄道・東京地下鉄・東海旅客鉄道」・P5d）|
| `level_complete` | bool | 乗降客時系列で構成事業者が全年揃うか（完全性）|

> ⚠ `flag_yoy` / `flag_covid` は**信頼性フラグ**（他の `*_lowbase` / `*_lown` と同じ flag 種別メトリクス）のため、駅属性ではなく**乗降客数の指標**として §2.2 に置く（除外・バッジが値経由で機能するよう metric_columns/station_values 化する・260727）。

### 2.2 乗降客数（S12・19列）→ `docs/passenger_aggregation.md`
| 列パターン | 数 | 型 | 説明 |
|---|---|---|---|
| `pax_{2011…2024}` | 14 | int | 各年の 1 日平均乗降客数（グループ合算・在の社のみ）|
| `rate_yoy` | 1 | float% | 直近前年比（2024 ÷ 2023）|
| `rate_covid` | 1 | float% | コロナ前→後（事業者単位）|

| `flag_covid` | 1 | int8 | `rate_covid` **注意**フラグ（被覆<100%／pre<2019／\|率\|>100%＝1）。バッジ用（`noticeFlagKey`）|
| `flag_covid_lown` | 1 | int8 | `rate_covid` **低分母**フラグ（\|率\|>100%＝1）。**除外用**（`reliabilityFlagKey`）・260731 |

## 3. データ特徴量を追加する定石（このリポジトリの流儀）

新しいオープンデータを駅×半径で足すときは、必ずこの順で進める：

1. **リサーチ**：候補データを**一次情報**（e-Stat / 国土数値情報 等）で確認（出典・**ライセンス**・年次・粒度・CRS）。実装前に候補と推奨を提示し合意する。
2. **設計ドキュメント**：`docs/<feature>.md` を作成。**実データを全数分析**した上で、データ定義・配置・スキーマ・品質検証（**全国計が公式値と一致**するか）・集約パラダイム・CRS・駅×半径ロジック・**半径別密度の実測**・増減率・信頼性フラグ・出力カラム一覧・設計決定ログを記す。
3. **合意**：設計（半径・年次・定義・列構成）をユーザーと確定してから実装に入る。
4. **実装**：ノートブックに節を追加。既存の共通関数（`_build_geom` / `aggregate_radii(_multi)` 等）を**流用**。**まずスタンドアロンで按分・列構築ロジックを検証**してからセル化する。
5. **監査**：フル再実行し、出力CSVを**全数点検**（既存列の完全再現・全国計の公式一致・**半径単調性**・増減率の再計算一致・NaN/丸め整合・負値・**特異値の実データ照合**）。
6. **記録**：docs に「**出力の総点検**」節を追記（バス §8.5・地価 §9.13・事業所 §10 と同形式）。

**原則**：品質最優先（時間は問わない）。**数値で裏取り**し、外れ値は「バグか実態か」を必ず実データで確認する。日本語・データ根拠・監査可能性を貫く。

### 集約パラダイム（実装の再利用点）
- **メッシュ（人口・将来人口・事業所/従業者）＝面積按分**：`_build_geom`（メッシュコード→ポリゴン）＋ `aggregate_radii(_multi)`（内側=全量・境界帯=面積按分）。値配列を差し替えるだけで新指標に流用可。
- **点の数（バス）＝カウント＋≤25m重複排除**（`cKDTree` 連結成分）。
- **点の代表値（地価）＝半径内の中央値**。
- **（将来）ポリゴン（災害リスク）＝半径円との重なり面積率** ＝ 新パラダイム。

## 5. スキーマ設計への含意（Step1→Step2）

- 現状 CSV は 595 列の**ワイド表**だが、DB では **正規化（`station_metrics(station_id, metric, radius_m, year, value)` 等）＋メトリクス・カタログ表**へ落とす前提（`.claude/CLAUDE.md` §3）。上記の命名規約 `{接頭辞}_{年}_{半径}` がそのまま `(metric, year, radius)` の 3 軸に対応する。
- **メトリクス・カタログ**（指標・単位・ラベル・半径・年・信頼性フラグの定義）は、UI と Gemini が同一の意味で消費するための単一の真実。本カラム一覧がその原型。
