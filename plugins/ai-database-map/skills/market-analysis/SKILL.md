# 出店の商圏分析（レシピ）

需要（人・カネの集積）と競合（同業の集積）を**駅×半径**で比べる。

**型**：[station-analysis の「分析の型」](../station-analysis/SKILL.md)に従う——
①要件はツールより先に 1 回（業種・候補が書かれていても**対応区分の確認**として復唱し、
残り——特に商圏半径と重視軸——を聞く）・回答後は既定を宣言して完走 ②候補駅は
`search_stations` で grp 解決（エリアなら `list_stations`） ③`build_dataset` は 1 回
④欠損・フラグ明示 ⑤正規化を脚注に明記 ⑥±20% ⑦比較表＋強み/弱み（**少数駅は preview
直組み可**） ⑧限界＋出典。以下は**この用途の差し込み**だけ。

## 聞くこと（型①の質問リスト）

1. **業種**：小売／飲食・宿泊／生活サービス・娯楽のどれに近いか（対応データが変わる）
2. **商圏の半径**：徒歩中心＝**500m**・自転車やバス圏＝1km・広域集客＝2km
3. **候補**：比較したい駅があるか。無ければエリア（市区町村など）から探すか
4. **重視**：需要の大きさ／競合の少なさ／成長性／地価（コストの proxy）のどれ寄りか

## データ（型③のプリセット・radiusM を商圏に合わせる）

- 共通：`["pop", "pop_gr", "pax", "inc_pc", "estab_n", "bus_n", "lp_med"]`
- 飲食・宿泊：＋`["sales_food", "emp_food_n", "emp_food_gr"]`
- 小売：＋`["sales_retail", "emp_trade_n", "emp_trade_gr"]`
- 生活サービス・娯楽：＋`["sales_leisure", "emp_life_n", "emp_life_gr"]`
- 広域からの集客力の目安：＋`["sales_dest", "sales_dest_gr"]`

## 読み方（proxy を proxy と言う）

- **需要**：`pop`（夜間人口）＋`emp_n` 系（**従業者＝昼間の活動量の proxy**——昼間人口データは
  無い）＋`pax`（駅前通行量の proxy）＋`inc_pc`（購買力）
- **競合**：同業種の従業者・事業所の集積（**店舗数そのものではない**）。`emp_同業 ÷ pop` の
  **密度比**も併記すると比較しやすい
- **コスト**：`lp_med` は地価公示＝土地の価格。**テナント賃料ではない**

## 売上データの限界（型⑧に差し込む・必ず言う）

- 売上（`sales_*`）は**市区町村の売上をメッシュの従業者数で按分した推計**——実測ではない
- **2021 年経済センサス＝2020 年の売上＝コロナ影響年**。2016 調査（=2015 年売上）との
  増減率（`*_gr`）を使うときは必ずこの前提を言う
- 本所一括計上の補正が調査年で非対称な団体があり、⚠ フラグの駅を黙って使わない

## してはいけないこと（この用途）

- 推計売上を実測のように言う／「必ず儲かる」類の断定
- 賃料・空き物件・視認性・歩行導線など**データに無いこと**の断定
- 競合 proxy（従業者・事業所）を「店舗数」と言い切る
- 2020 年（コロナ影響）の注記省略
