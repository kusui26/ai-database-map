# 出店の商圏分析（方法論）

需要（人・カネの集積）と競合（同業の集積）を**駅×半径**で比べる。
データの作法は [analyze-csv](../analyze-csv/SKILL.md) に従う。

## 1. 要件を先に聞く（ツールより先・1 回だけ）

**初回の応答では分析を始めない。** 依頼文に業種や候補駅が書かれていても、それは復唱に
留め（業種は**対応するデータ区分の確認**として返す）、残りの項目——特に**商圏半径と
重視軸**——を確認してから走る。

1. **業種**：小売／飲食・宿泊／生活サービス・娯楽のどれに近いか（対応データが変わる）
2. **商圏の半径**：徒歩中心＝**500m**・自転車やバス圏＝1km・広域集客＝2km
3. **候補**：比較したい駅があるか（あれば駅名）。無ければエリア（市区町村など）から探すか
4. **重視**：需要の大きさ／競合の少なさ／成長性／地価（コストの proxy）のどれ寄りか

回答をもらったら、残る曖昧さは**合理的な既定を宣言して**同じ応答で最後まで実行する
（[station-recommendation](../station-recommendation/SKILL.md) と同じ規範。聞き直さない）。

## 2. 対象集合

- 候補駅の指定あり → `mcp__plugin_ai-database-map_station-data__search_stations` で grp を解決
  （同名駅は都道府県で確認）
- エリアから → `mcp__plugin_ai-database-map_station-data__list_stations`（municipality 前方一致）

## 3. データセット（1 回で取る・radiusM を商圏に合わせる）

`mcp__plugin_ai-database-map_station-data__build_dataset`。業種別の推奨 metrics：

- 共通：`["pop", "pop_gr", "pax", "inc_pc", "estab_n", "bus_n", "lp_med"]`
- 飲食・宿泊：＋`["sales_food", "emp_food_n", "emp_food_gr"]`
- 小売：＋`["sales_retail", "emp_trade_n", "emp_trade_gr"]`
- 生活サービス・娯楽：＋`["sales_leisure", "emp_life_n", "emp_life_gr"]`
- 広域からの集客力の目安：＋`["sales_dest", "sales_dest_gr"]`（目的地としての売上）

## 4. 読み方（proxy を明示して使う）

- **需要**：`pop`（夜間人口）＋`emp_n` 系（**従業者＝昼間の活動量の proxy**——昼間人口データは
  無い）＋`pax`（駅前通行量の proxy）＋`inc_pc`（購買力）
- **競合**：同業種の従業者・事業所の集積（**店舗数そのものではない**——proxy と明示）。
  `emp_同業 ÷ pop` のような**密度比**も併記すると比較しやすい
- **コスト**：`lp_med` は地価公示＝**土地の価格**。**テナント賃料ではない**（proxy と明示）

## 5. 売上データの限界（必ず言う・削らない）

- 売上（`sales_*`）は**市区町村の売上をメッシュの従業者数で按分した推計**——実測ではない
- **2021 年経済センサス＝2020 年の売上＝コロナ影響年**。2016 調査（=2015 年売上）との
  増減率（`*_gr`）を使うときは必ずこの前提を言う
- 本所一括計上の補正が調査年で非対称な団体があり、⚠ フラグの駅を黙って使わない

## 6. 比較と出力

- 単位が違う値を合成するなら**正規化（方法を脚注に明記）＋重み明示＋±20% 敏感度**。
  合成せず指標別の並記でもよい（少数駅の比較ならその方が読みやすい）
- **少数駅（〜5 駅程度）の並記比較**は、`build_dataset` 応答の preview（先頭 5 行）と
  meta から直接表を組んでよい（値の出所はサーバ製の CSV）。多数駅・合成スコア・密度比の
  計算は CSV をローカル（pandas 等）で行う
- 出力：候補駅の**比較表**（実値＋単位・年次・半径）＋各駅の強み/弱み 1〜2 行＋
  **限界**（§4 の proxy・§5 の推計・半径は駅の代表点基準）＋**出典**（meta の sources）

## してはいけないこと

- 推計売上を実測のように言う／「必ず儲かる」類の断定
- 賃料・空き物件・視認性・歩行導線など**データに無いこと**の断定
- 競合 proxy（従業者・事業所）を「店舗数」と言い切る
- カタログ外キーの発明／2020 年（コロナ影響）の注記省略／限界・出典の省略
