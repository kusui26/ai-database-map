# 指標キーの規約（詳細）

## 命名

- カタログキーは `{接頭辞}_{年}_{半径}`。増減率は `{接頭辞}_{新しい年}_{古い年}_{半径}`
  （例 `pop_gr_2020_2015_1km` ＝ 1km 圏人口の 2015→2020 増減率）。
- **正確なキーは必ず `get_metrics_catalog` で確認する**。年次・半径の組み合わせは
  指標ごとに違う（無い組み合わせがある）。

## ファミリ名の例（既定：半径 1km・直近）

| ファミリ     | 意味                   |
| ------------ | ---------------------- |
| `pop_gr`     | 人口の増減率           |
| `lp_med`     | 地価の中央値           |
| `lp_gr`      | 地価の増減率           |
| `bus_n`      | バス停数               |
| `rate_covid` | 乗降客数のコロナ前後比 |

上記は例であり、全一覧・正確な単位・利用可能な年次はカタログを引くこと。

## 半径

500 / 1000 / 2000 / 5000 / 10000 / 20000 m の 6 段（事前計算値）。任意半径は不可。
半径非依存の指標（駅そのものの値：乗降客数など）では `radiusM` は無視される。

`radiusM` は**各駅の周りを何 m で集計するか**で、探す範囲ではない。「竹橋から 5km 以内の駅」は
`near: {station: "竹橋", withinM: 5000}` で絞る（`rank_stations` / `compare_growth` / `list_stations` /
`build_dataset` で同じ）。返却の各駅に起点からの距離（`distance`）が付くので、距離は自分で計算しない。

## 信頼性フラグ

- ランキングの `flagged: true`・散布の `excludeLowN` は「母数が小さい／極端値」の注意。
- 既定では表示に含めてよいが、**⚠ を付けて理由を書く**。統計的な結論に使うときは除外を検討し、
  除外したら件数を明示する。

## 0 件のとき

会社・路線・市区町村・起点の駅の名前はサーバが解決する（路線は利用者の呼ぶ路線＝運行系統。「山手線」は環状の 30 駅）。
決まらないとき（同じ名前の別路線・区「中区」・駅「府中」・データに無い名前）は図を作らずに `problems`（候補つき）を返すので、
それに従って呼び直すか利用者に確かめる。
0 件（`noFigure`）は名前ではなく**条件の組合せ**のせいなので、条件を緩めるか 0 件だったことを伝える。
応答の `note` / `hint` に従い、勝手に「データが無い」と結論しない。
