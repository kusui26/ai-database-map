# 住む駅のおすすめ（レシピ）

「おすすめ」は**好み×データ**。重みはユーザーのもの——**勝手に決めて断定しない**。

**型**：[station-analysis の「分析の型」](../station-analysis/SKILL.md)に従う——
①要件は**ツールより先に 1 回**で聞き、回答後は既定を宣言して同じ応答で完走
②集合はまとめ呼び（0 件 note に従う） ③`build_dataset` は 1 回（notes を本文に写す・
CSV/meta 保存） ④欠損・フラグ・`uncovered` を黙って使わない ⑤**正規化**を脚注に明記・
災害は**線形**加点しない ⑥**±20%** 敏感度 ⑦表＋効いた要因/弱点 ⑧限界（**代表点**基準ほか）＋
**出典**。以下は**この用途の差し込み**だけ。

## 聞くこと（型①の質問リスト）

1. **予算重視か、資産価値重視か**（買いやすさ vs 値下がりしにくさ）
2. **通勤先・使う路線**（⚠ 駅間の**所要時間データは持っていない**——「直通路線での近似」に
   なることをこの時点で伝える）
3. **災害リスクの許容度**：避けたい種別（洪水・土砂など）と、**足切り**（除外）か
   **減点**（順位を下げる）か
4. （任意）にぎわい重視か、静けさ重視か

重みの**初期値の例**として提示し、そのまま使ってよいか確認する：

| プリセット           | 将来人口 | 実績人口 | 地価トレンド | 地価水準 | 乗降回復 | 乗降水準 |
| -------------------- | -------- | -------- | ------------ | -------- | -------- | -------- |
| ファミリー（持続性） | 0.30     | 0.20     | 0.20         | 0.00     | 0.15     | 0.15     |
| 資産性重視           | 0.20     | 0.10     | 0.25         | 0.20     | 0.10     | 0.15     |
| 利便性重視           | 0.20     | 0.15     | 0.15         | 0.00     | 0.20     | 0.30     |

**既定宣言の例**（型①・回答後に聞き直さないための定型）：

- 通勤条件 →「所要時間データは無いため、◯◯へ直通する路線の駅で近似します（境界駅は注記）」
- 「予算重視」×ファミリー初期値（地価水準 0.00）→「地価水準 0.15（**安いほど良い**向き）に
  振り替えます（地価トレンド 0.20→0.10・将来人口 0.30→0.25）」のように**採用した調整を明示**

## データ（型③のプリセット）

`build_dataset` に **`includeHazard: true`**。半径 1km・直近：

```json
[
  "pax",
  "rate_covid",
  "pop",
  "pop_gr",
  "pop_gr_pred_2024_2040_1km",
  "lp_med",
  "lp_gr",
  "bus_n",
  "estab_n"
]
```

将来人口はファミリの既定が短期スパンに解決されるため **2040 到達のキーを明示**する。

## 災害の扱い（型⑤の差し込み）

- **足切り**：指定種別の `hazard_*_level` が閾値以上（例 danger 以上）を除外し、駅数と代表例を言う
- **減点**：段階減点（例 warning −0.05・danger −0.15・critical −0.30）を明示して適用

## この用途の限界（型⑧に差し込む）

1. **地価は地価公示（土地の価格）でありマンション価格そのものではない**（代理指標）
2. 通勤条件は**路線による近似**（所要時間データは持たない）
3. ハザードは想定最大規模の**「もし起きたら」**であり現在ではない。判定は代表点 1 点。
   **「安全です」とは書かない**（none＝該当なし・`uncovered`＝図なし）

## してはいけないこと（この用途）

- **ハザードの線形加点**／「安全です」「心配ありません」
- 好み・重みを確認する前におすすめを確定する／敏感度に触れずに順位を断定する
