# 輸送計画・ダイヤ検討の需要分析（方法論）

**このデータで言えるのは「駅ごとの乗降需要と沿線ポテンシャル」まで。**
列車ダイヤ・駅間の断面輸送量・混雑率・時間帯別・OD（発着地）データは**持っていない**——
「需要側の材料」に徹し、増発・減便など**運行計画そのものを断定しない**。
データの作法は [analyze-csv](../analyze-csv/SKILL.md) に従う。

## 1. 要件を先に聞く（ツールより先・1 回だけ）

**初回の応答では分析を始めない。** 依頼文に対象や目的の**一部**が書かれていても、
それは復唱に留め、**残りの項目を確認してから**走る（①〜③がすべて明示されている・
「確認不要」と書かれている場合だけ即実行してよい）。

1. **対象**：会社・路線（・区間）。路線名は正式名称で確認
2. **何の検討材料か**：例）増発/減便の検討・パターン見直し・設備投資・中期計画
3. **時間軸**：直近の回復（2019→現在）か、中長期（10〜20 年・将来人口）か
4. （任意）重視したい指標・比較したい他路線

回答をもらったら、残る曖昧さは**合理的な既定を宣言して**同じ応答で最後まで実行する
（[station-recommendation](../station-recommendation/SKILL.md) と同じ規範。聞き直さない）。

## 2. 対象集合

`mcp__plugin_ai-database-map_station-data__list_stations` の `operators` / `routes` で取る
（**複数路線はまとめて 1 回**）。件数と `truncated` を言う。
路線名は**会社名を含まないデータの正式名称**（例「東横線」）。綴りが不確かなら、
①短い通称で 1 回 → ②0 件なら `operators`（会社の正式名称・例「東急電鉄」）で全駅を 1 回、
の**合計 2 回まで**（当てずっぽうの再試行を重ねない。応答の note に従う）。

## 3. データセット（1 回で取る）

`mcp__plugin_ai-database-map_station-data__build_dataset`。推奨の初期 metrics：

```json
["pax", "rate_covid", "pax_rate", "pop", "pop_gr", "pop_gr_pred_2024_2040_1km", "emp_n", "estab_n"]
```

- **乗降の時系列**は `"pax"` ＋ `years` 配列（例 `[2011, 2014, 2019, 2022, 2024]`。
  傾きの回帰まで見るなら 2011〜2024 を全部並べてよい——値列上限 60 に収まる）
- **必ず 1 回の呼び出しにまとめる**（pax 14 年＋上記 7 指標でも上限に余裕がある。
  指標ごと・年ごとに build_dataset を分割しない）
- 半径は既定 1km（駅勢圏の近似）。広域比較なら 2km
- 上記の推奨 metrics は**事前のカタログ照会なしでそのまま渡してよい**（ファミリは自動解決され、
  使われた既定は応答の notes に返る）。他の候補を探すときだけ
  `mcp__plugin_ai-database-map_station-data__get_metrics_catalog` を **category 単位で 1〜2 回**
  （指標ごとに引き直さない）

## 4. 前処理と読み方（proxy を明示）

- **乗降客数＝その駅の利用**であって、駅間を**通過する断面需要ではない**（必ず注記）
- `rate_covid` のフラグ（被覆・低分母 ⚠）を黙って使わない。欠損は件数を言う
- `emp_n`（従業者）は**昼間の活動量の proxy**（昼間人口データは無い）

## 5. 分析パターン（順位の断定より構造を見せる）

- **回復 × 将来**の 4 象限：`rate_covid`（コロナ前後回復）×`pop_gr_pred`（将来人口）で駅を分類
  （例：回復済×将来増＝需要堅調／未回復×将来減＝要注視）
- **トレンドの傾き**：`pax` 系列の回帰（手法を明記。欠損年はどう扱ったかも）
- 合成スコアを作る場合は**正規化（方法を脚注に明記）＋重みの明示**。閾値・重みは±で振って
  分類の入れ替わりを確認する（僅差はそう言う）

## 6. 出力の形

- 路線内の駅を「堅調・回復途上・要注視」等に**分類した表**（実値＋単位・年次つき）＋
  各駅に根拠 1〜2 行
- **限界（必ず・削らない）**：①ダイヤ・断面輸送量・混雑率・時間帯別・OD・定期/定期外の内訳は
  持たない ②**この推奨文をそのまま使う**：「乗降客数は各駅の利用者数であり、駅間を通過する
  断面需要（輸送量）ではない」 ③将来人口は R6 推計という**一つの前提**（幅を持って読む）
  ④半径円は駅勢圏の近似 ⑤出典（meta の sources を列挙）

## してはいけないこと

- 増発・減便・所要時間・運行本数など**運行計画の断定や提案の言い切り**
  （「〜の検討材料になる」までに留める）
- 持っていないデータ（混雑率・断面・時間帯）を推測で数値化する
- カタログ外キーの発明／回復率の基準年（2019）を無断で変える／限界・出典の省略
